# Terraform Provider Template

A starting point for writing your own Terraform provider. It is a small, working provider built on the [Terraform Plugin Framework](https://developer.hashicorp.com/terraform/plugin/framework), with tests, generated documentation, and release configuration.

Repository: <https://github.com/jreidell/terraform-provider-template>

The provider has one resource, `template_server`, which fetches UUIDs from an HTTP API and stores them in state. It is deliberately simple, and covers the parts every provider needs: provider configuration, an API client, a resource with create, update, and delete, plan modification, validation, and acceptance tests.

## Repository layout

```
docs/      Research and design notes
src/       The Go provider
```

| Path | Purpose |
| --- | --- |
| `src/main.go` | Entry point. Starts the provider server. |
| `src/internal/provider/` | Provider and resource implementations, with acceptance tests. |
| `src/internal/uuidclient/` | The API client. Replace it with a client for your API. |
| `src/examples/` | Terraform configurations, also used in the generated docs. |
| `src/docs/` | Registry documentation generated by `tfplugindocs`. Do not edit by hand. |
| `docs/provider-development-options.md` | Which libraries and languages can be used to write providers. |
| `docs/modernization-notes.md` | How this template differs from the SDKv2 example it started from. |

## Requirements

- [Go](https://go.dev/dl/) 1.25 or later
- [Terraform](https://developer.hashicorp.com/terraform/install) 1.0 or later

## Build and test

Run these from `src`.

```sh
go build -o bin/ .          # build the provider binary into bin/
go test ./...               # unit tests
```

Acceptance tests run the real Terraform CLI against the provider. They use a local fake API, so they need no network access or credentials. Set `TF_ACC` to enable them:

```sh
TF_ACC=1 go test ./...              # bash
$env:TF_ACC = "1"; go test ./...    # PowerShell
```

A `GNUmakefile` wraps the same commands (`make test`, `make testacc`, `make docs`) if you have `make`.

## Try it with Terraform

Tell Terraform to use your local build instead of downloading from a registry. Create a CLI configuration file, for example `dev.tfrc`, pointing at the directory that contains the binary:

```hcl
provider_installation {
  dev_overrides {
    "jreidell/template" = "/absolute/path/to/src/bin"
  }
  direct {}
}
```

Then, in a directory containing a configuration such as the one below:

```sh
export TF_CLI_CONFIG_FILE=/absolute/path/to/dev.tfrc    # bash
$env:TF_CLI_CONFIG_FILE = "C:\path\to\dev.tfrc"         # PowerShell

terraform apply
```

With `dev_overrides` you skip `terraform init`. Terraform prints a warning that overrides are in effect, which is expected.

```hcl
terraform {
  required_providers {
    template = {
      source = "jreidell/template"
    }
  }
}

provider "template" {}

resource "template_server" "test" {
  uuid_count     = 5
  creation_delay = 5
}

output "generated_uuids" {
  value = template_server.test.uuids
}
```

By default the provider calls the public API at `uuidtools.com`. Set the `endpoint` provider attribute or the `TEMPLATE_ENDPOINT` environment variable to use a different one.

## Make it your own

1. **Rename the module.** Replace `github.com/jreidell/terraform-provider-template` in `go.mod` and in every import with your repository path. The repository must be named `terraform-provider-<name>` to publish to the Terraform Registry.
2. **Rename the provider.** Change `resp.TypeName` in `internal/provider/provider.go`, the `Address` in `main.go`, the `template` key in the test provider factories, and `--provider-name` in the `GNUmakefile`. Replace `jreidell/template` in the examples with `<your namespace>/<name>`. On the public registry the namespace is your GitHub user or organization.
3. **Replace the client.** Swap `internal/uuidclient` for your API client and build it in the provider's `Configure` method. Add credentials to the provider schema, marked `Sensitive`.
4. **Write your resources.** Use `server_resource.go` as a pattern. Register each new resource in the provider's `Resources` method, and data sources in `DataSources`.
5. **Regenerate the docs.** From `src`, run `go run github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs@v0.25.0 generate --provider-name <name>`.

## Releasing

`src/.goreleaser.yml` and `src/terraform-registry-manifest.json` follow the layout the Terraform Registry expects: one zip per platform, a SHA256SUMS file, and a GPG signature. See [Publishing providers](https://developer.hashicorp.com/terraform/registry/providers/publishing) for the registry side. The registry expects the provider at the root of its repository, so publish from a repository whose root is the contents of `src`.

## Other languages

Go is the only language HashiCorp supports for providers. Community SDKs exist for C#, Python, and Rust, with caveats. See [docs/provider-development-options.md](docs/provider-development-options.md).
